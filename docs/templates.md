# 앱 템플릿 설치

프로젝트의 **템플릿** 화면에서 시작할 앱을 고릅니다. 별도 저장소를 준비하지 않아도
버전이 고정된 예제 소스로 기존 빌드·배포 과정을 시작할 수 있습니다.

| 템플릿 | 생성 항목 | 필요한 입력 |
| --- | --- | --- |
| Next.js + PostgreSQL | 웹 앱과 PostgreSQL DB | 없음 |
| FastAPI | Python 웹 앱 | 없음 |
| Discord 봇 | 백그라운드에서 실행되는 봇 | Discord 봇 토큰 |

## 사용 방법

1. 프로젝트에서 설치할 환경과 템플릿을 선택합니다.
2. 필요한 값을 입력하고 생성할 앱·DB를 확인합니다. 이름 충돌, 권한, 사용량 제한이 있으면 설치 전에 안내합니다.
3. 설치 후 같은 화면에서 준비 상태를 확인합니다. 화면을 닫아도 서버 작업은 계속됩니다.
4. 실패한 설치는 **다시 시도**합니다. 진행 중이거나 이미 완료된 작업은 중복 생성하지 않습니다.
   앱의 배포 상세 화면에서 로그를 확인할 수 있습니다.

같은 요청을 다시 전송해도 설치와 앱·DB가 중복 생성되지 않습니다. 같은 요청에 입력값만
바꿔 보내면 충돌로 거부합니다. 템플릿이 사용하는 앱 이름이 이미 있으면 다른 프로젝트나
비어 있는 환경을 사용하세요. 이번 버전에는 설치 중 이름 변경 기능이 없습니다.

## 저장·실행 방식

- 설치 기록, 앱·DB, 빌드 작업, 암호화한 입력값을 하나의 트랜잭션으로 저장합니다.
- 봇 토큰은 공개 설치 응답이나 소스 다운로드에 포함하지 않습니다. 실행 시 비밀값 참조로 전달합니다.
- 빌더는 서버에 포함된 카탈로그와 소스 묶음의 해시를 확인합니다. 요청에서 받은 임의 URL이나 파일 경로를 실행하지 않습니다.
- PostgreSQL이 필요한 앱은 DB 준비가 끝난 뒤 빌드를 시작합니다. 모든 템플릿은 기존 Dockerfile 빌드 경로를 사용합니다.
- 설치 목록과 재시도는 프로젝트·환경에 속한 현재 사용자의 권한을 확인합니다.

소스 API는 `/templates/{catalogId}/versions/{catalogVersion}/source`이며,
`catalogDigest`와 `sourceDigest`가 필요합니다. 응답은 파일별 경로·모드·해시와 Base64 내용을
담은 JSON입니다. 설치에 사용되는 소스와 같은 무결성 검사를 통과해야 다운로드할 수 있습니다.

## 운영 설정과 제한

기능은 기본 비활성입니다. 화면에 준비 중으로 표시되면 사용자가 설정할 값이 아니라
운영자가 확인해야 할 서버 설정입니다. Helm의 `operational` 설정은 다음과 같습니다.

```yaml
operational:
  enabled: false
  implementationAvailable: false
  protocolVersion: 1
  contractDigest: ''
  releaseRevision: ''
  releaseSourceClean: false
```

활성화에는 구현 가용성, 프로토콜 2, 검증한 계약 해시와 릴리스 커밋, 깨끗한 소스 상태가
모두 필요합니다. 값만 채웠다고 출시 검증이 끝난 것은 아닙니다. 실제 클러스터의 빌더,
레지스트리, 서명 검증, DB 제공자, Secret 암호화·권한 설정을 함께 확인해야 합니다.
활성화할 때 `runtimeSecrets.existingSecret`에는 API와 같은
`RAIBITSERVER_SECRET_ENCRYPTION_KEY`가 있어야 합니다. 비활성 상태에서는 오케스트레이터에 이 키를 주입하지 않습니다.
공유 운영 플래그를 켜면 다른 운영 기능에도 영향을 주므로 운영자가 릴리스 단위로 판단합니다.

이번 범위는 최초 설치·상태 조회·실패 재시도입니다. 템플릿 업그레이드·이전 버전 복원,
사용자 정의 템플릿, 설치한 소스의 GitHub 저장소 생성은 포함하지 않습니다.
Discord 봇 템플릿과 프로젝트의 Discord 배포 알림은 별도 기능입니다.
